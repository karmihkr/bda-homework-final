# Генератор учебного комплекта данных

Комплект для дисциплины **Б1.В.ДВ.15.10 «Big Data Analytics / Аналитика больших
данных»** (09.03.01, профиль «Инженерия информационных систем»).

Предметная область — услуги связи. Данные **полностью синтетические**: они
воспроизводят структуру и статистические свойства отраслевых выгрузок, но не
содержат ни одной реальной записи. Наименование оператора не используется:
в материалах фигурирует «условный оператор связи».

---

## Быстрый старт

```bash
python -m tdg --level S --out ./out --seed 20260827 --clean   # генерация
python verify.py ./out                                        # 26 проверок
python reference_answers.py ./out --out ответы.md             # эталонные ответы
python variants.py ./out --students 30 --group 1              # варианты
python churn_check.py ./out                                   # эталон этапа 5
```

Требуется Python 3.10+, `numpy` и `pandas`. Внешние сетевые ресурсы не нужны.

## Уровни объёма

| Уровень | Записей о соединениях | Период | Сырой слой | Время генерации |
|---|---|---|---|---|
| `XS` | 1 млн | 30 суток | ≈0,17 ГБ | ~10 с |
| `S` | 10 млн | 90 суток | ≈1,5 ГБ | ~1,5 мин |
| `M` | 300 млн | 24 месяца | ≈44 ГБ | ~50 мин |
| `L` | 1 млрд | 24 месяца | ≈145 ГБ | ночной прогон |

Схемы на всех уровнях идентичны: код, отлаженный на `S`, переносится на `M`
без изменений. Мощность справочника тарифных планов намеренно не растёт —
это условие задания о широковещательном соединении.

## Что получается на выходе

```
out/
  raw/                        сырой слой — то, что «приходит от источника»
    cdr/dt=ГГГГ-ММ-ДД/cdr.csv             записи о соединениях
    tickets/dt=…/tickets.csv              обращения абонентов (текст)
    telemetry/dt=…/telemetry.jsonl        телеметрия узлов сети
    dictionaries/                         справочники снимками на 5 дат
  late_delivery/              выгрузки, «пришедшие с опозданием»
  reference/                  материалы преподавателя — обучающимся не выдаются
    passport.json                         паспорт комплекта
    defect_ledger.csv                     ведомость дефектов
    aggregates_daily.csv                  эталонные агрегаты
    subscribers_scd2_truth.csv            истинная история справочников
    nodes_scd2_truth.csv
    churn_truth.csv                       истинная разметка оттока
  MANIFEST.csv                контрольные суммы всех файлов
```

Колоночный формат **не создаётся намеренно**: конвертация сырого слоя в
колоночный и сравнение форматов — задание второго этапа сквозного проекта.

## Воспроизводимость

Результат однозначно определён парой «версия генератора + начальное состояние».
Повторный запуск с тем же `--seed` даёт **побайтно те же файлы**: проверено
сверкой всех 109 контрольных сумм на уровне `XS`. Другое значение `--seed`
меняет весь комплект, кроме справочников географии и календаря, которые от
него не зависят.

Каждые сутки порождаются независимым потоком случайных чисел, производным от
общего начального состояния и номера суток. Поэтому отдельную суточную
партицию можно перегенерировать, не пересчитывая период целиком.

Университет после генерации сверяет `MANIFEST.csv` с переданным манифестом и
убеждается, что располагает ровно тем набором, который описан в комплекте
оценочных средств.

## Индивидуализация заданий

Раздавать персональные копии рабочего уровня не нужно: при 30 обучающихся это
900 ГБ вместо 44 ГБ. Уровень `M` существует на стенде в единственном
экземпляре, а индивидуальность обеспечивается сочетанием аналитического
вопроса, закреплённого филиала и периода анализа. Личный отладочный набор
уровня `S` выдаётся с индивидуальным `--seed`.

## Проверка соответствия требованиям

`verify.py` прогоняет 26 проверок, каждая из которых соответствует строке
таблицы «Требования, выведенные из заданий» приложения к РПД. Проверки с
пометкой `[БЛОК]` отвечают блокирующим требованиям: без них соответствующее
задание невыполнимо.

Текущее состояние: **26 из 26 на уровне `S`**, невыполненных блокирующих нет.
На уровне `XS` проверка дрейфа неприменима — период втрое короче окна дрейфа.

## Свойства, заложенные намеренно

| Свойство | Где | Для какого задания |
|---|---|---|
| Перекос по абонентам: верх 0,1 % → 35 % записей | `cdr.subscriber_key` | Диагностика перекоса, этап 3 |
| Перекос по узлам: верх 1 % → 45 % | `cdr.node_id` | То же |
| Незаполненный узел, 5 % | `cdr.node_id` | Перекос при соединении |
| Малый справочник, 51 строка | `dictionaries/tariffs.csv` | Широковещательное соединение |
| Запаздывание до суток, роуминг | `cdr.ingest_ts` | Окна агрегации, этап 4 |
| Повреждённая суточная выгрузка | `raw/cdr/dt=…` | Разбор сбойного прогона |
| Три пропущенных суток | `late_delivery/` | Обратное заполнение |
| История справочников, ~15 % | снимки на 5 дат | Медленно меняющиеся измерения |
| Ловушка утечки данных | `tickets.retention_contact` | Проверка утечки, этап 5 |
| Дрейф: доля передачи данных 57 % → 71 % | `cdr.service_type` | Деградация модели |
| Спад потребления перед уходом абонента | `cdr` | Честный сигнал оттока, этап 5 |
| Рост обращаемости перед уходом | `tickets` | То же |
| 11 типов дефектов качества | `cdr`, `tickets` | Проверки качества, профилирование |

Ловушка утечки устроена так же, как в практике: признак «контакт с
подразделением удержания» проставляется **после** того, как абонент отнесён к
склонным к оттоку.

Важно: отток **не случаен** — он определяется латентной неудовлетворённостью,
которая порождает наблюдаемые предвестники (спад потребления, рост
обращаемости). На эталонном комплекте честные признаки дают AUC около **0,74**,
добавление ловушки повышает оценку. Если честные признаки дают AUC около 0,5,
комплект собран с ошибкой: задание становится невыполнимым для того, кто
правильно уберёт утечку. Проверяется командой `python churn_check.py ./out`
и автоматической проверкой №26.

## Ведомость дефектов

Хранится как правило воспроизведения — тип, целевая и фактическая доля,
начальное состояние, — а не как поимённый перечень записей: при 300 млн записей
перечень затронутых идентификаторов сам по себе занял бы сотни мегабайт.
Восстановить перечень позволяет `verify.py` по тем же правилам.

## Настройка

Все параметры собраны в `tdg/config.py`: уровни объёма, целевой профиль
перекоса, доли дефектов, параметры запаздывания, сезонность, дрейф, отток.
Остальные модули читают их оттуда и нигде не дублируют.

## Состав

| Файл | Назначение |
|---|---|
| `tdg/config.py` | Параметры комплекта |
| `tdg/refs.py` | Справочники, история изменений, веса перекоса |
| `tdg/facts.py` | Посуточная генерация фактов |
| `tdg/defects.py` | Внедрение дефектов и ведомость |
| `tdg/emit.py` | Запись партиций, повреждение выгрузки, манифест |
| `tdg/__main__.py` | Точка входа |
| `verify.py` | 26 проверок соответствия требованиям |
| `reference_answers.py` | Эталонные ответы к заданиям пяти этапов |
| `variants.py` | Раздача вариантов и проверка сопоставимости нагрузки |
| `churn_check.py` | Эталонное решение этапа 5: честный сигнал против утечки |

## Ограничения

Генератор проверен на уровнях `XS` и `S`. Оценки объёма и времени для `M` и `L`
получены экстраполяцией: 158 байт на запись сырого слоя. Первый прогон уровня
`M` следует выполнить до передачи комплекта и уточнить эти значения в паспорте.
